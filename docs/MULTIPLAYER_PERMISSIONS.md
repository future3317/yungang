# 多人权限与席位规则

## 权限边界

房主只能管理 Lobby、点亮、暂停和恢复房间，不能代替多设备席位提交行动。多设备行动由 `X-Seat-Token` 推导出服务端席位，再由游戏状态校验当前行动者。客户端传入的 `player_id` 不参与正式房间鉴权。

单人和本地协作使用创建者凭证控制当前活跃角色；多设备模式只允许对应席位提交行动。非当前席位可以读取公共地图、任务、路线、项目和事件信息，但不能提交当前席位的行动、使用当前席位手牌或确认角色升级。

## 信息可见性

多设备读取游戏状态时，其他席位的文化手牌和策略牌会被服务端清空；自己的手牌仍可见。单人和本地协作保留完整共享屏幕信息，因为它们的规则就是共同使用一台设备。

## 冲突与恢复

所有行动携带 `expected_revision`。版本不一致返回结构化 `revision_conflict` 和最新状态，前端清空旧的目标选择后重新同步。无效 token、非当前行动者、未准备席位、已开始房间和暂停房间均返回明确的中文恢复建议。

## 本地交接

本地协作在结束行动后显示席位交接层，提示下一位同行者接过屏幕后继续。交接只改变操作上下文，不改变服务端规则和共享状态。
