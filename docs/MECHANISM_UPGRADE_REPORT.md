# 《石窟光谱》机制与内容升级报告

## 一、现有机制诊断

| 维度 | 当前状态 | 诊断 | 本包处理 |
|---|---|---|---|
| 核心循环 | AP 驱动的移动、探索、贡献、修护、准备、技能与事件结算 | 基础循环成立，已经不是飞行棋；但部分行动之间的因果关系偏弱 | 通过场景牌库、任务组合、路线治理和项目阶段强化因果链 |
| 回合决策 | 玩家根据 `legal_actions` 选择行动 | 行动是否合法清晰，但“选哪张证据、为何保留、何时打出”缺少组合理由 | 36 张文化证据全部增加证据用途、即时用途、组合标签和战略定位 |
| 移动与路线 | 路线成本、阻断、勘察、修护、建立连接 | 路线系统已有状态，但不同情景对路线的依赖不够鲜明 | 四个场景分别配置启用节点、阻断数量、路线向卡和路线事件 |
| 探索 | 从公开市场选牌并获得研究线索 | 有信息不完全，但原牌库大量同质化，市场选择价值不足 | 重做卡牌效果分布，场景使用不同卡池和数量权重 |
| 贡献 | 以领域和来源完成地点任务 | 当前后端主要按 `domain` 判断可贡献，组合字段尚未进入规则层 | 在任务和卡牌中补全 `combo_requirement`、`combo_tags` 等 P1 字段 |
| 修护 | 降低节点或路线风险 | 是明确的风险管理工具，但事件与修护之间缺少情景化提示 | 18 个事件增加预告、缓解提示、风险标签和事件链 |
| 项目 | 依次完成探索、贡献、修护阶段 | 已支持按 `action_type` 推进，但各项目原本结构接近 | 重做 8 个项目，提供不同阶段顺序、需求、奖励和战略用途 |
| 事件 | 回合末结算，少数事件有选择 | 基础压力存在，但原事件同质化，策略改变有限 | 18 个事件分为节点损伤、路线压力、信息风险和正向机会 |
| 角色 | 四个角色拥有主动能力 | 基础互补成立，但升级只是存储 ID，效果未接入 | 完成角色定位和 8 个升级方向，并列入 P1 接入说明 |
| 目标与胜负 | 影响、领域、项目、路线、稳定节点 | 目标类型已存在，但叙事提示与策略说明不足 | 5 个目标补充描述、进度文案、权重和策略提示 |
| 单人体验 | 当前服务端要求 2–4 名玩家 | 单人尚不能直接创建，需要虚拟控制两名角色 | 四场景加入 `solo_rules`，列入 P1 后端改造 |
| 多人体验 | 交换、多人任务与角色分工 | 容易出现一名玩家替全队计算的“领袖问题” | 多人项目、计划标记、来源分散和角色节点能力增加并行责任 |

### 应保留

- 服务端 `legal_actions` 为唯一合法性来源。
- revision 冲突处理。
- 每回合有限 AP。
- 公开市场、手牌、档案区与弃牌区。
- 节点风险、路线状态和事件预告。
- JSON 内容驱动与固定 seed。

### 应合并或重做

- 所有“只增加 1 影响”的同质化文化牌。
- 只按领域匹配、没有组合理由的证据贡献。
- 同一阶段模板复制到所有项目。
- 配置存在但尚未进入实际牌库或效果系统的行动牌、升级和事件链。
- 只改变回合数与资源、不改变内容池的情景差异。

## 二、新版核心机制

### 一句核心体验

**玩家用有限行动在不完整信息下拼合文化证据，同时治理路线与遗产风险，共同把一张脆弱的遗产网络维持到核心项目完成。**

### 一局循环

1. 创建情景并按 seed 生成节点、路线阻断、文化牌和事件顺序。
2. 揭示本轮事件预告。
3. 玩家放置计划标记，表明拟处理的节点、路线或项目。
4. 玩家依次使用 AP 移动、探索、交换、贡献、修护、勘察路线、建立连接或准备事件。
5. 证据可以二选一：贡献到任务/项目，或打出即时效果。
6. 最后一名玩家结束回合后结算事件。
7. 更新节点、路线、项目、公共目标和胜负状态。
8. 在限定回合内完成核心项目与场景目标。

### 决策来源

- 路线是否畅通、风险是否值得提前处理。
- 公开市场只有三张牌，未知牌堆形成信息不完全。
- 每张文化证据兼具“证据用途”和“即时用途”。
- 项目阶段需要不同领域、来源、玩家参与和资源。
- 事件预告公开结果类型，但目标与后果可能需要进一步调查。
- 角色能力和节点能力鼓励不同玩家承担不同责任。

### 三段节奏

- **开局：调查与定向。** 确定核心项目缺口，收集研究线索，避免过早消耗关键牌。
- **中局：组合与治理。** 玩家分散处理节点、路线和项目，交换来源证据，建立稳定通道。
- **结局：集中与保全。** 汇集五域证据完成核心项目，同时防止核心节点关闭或事件压力失控。

## 四、字段兼容性说明

### 现有后端可直接读取并生效的字段

- 场景：`enabled_site_ids`、`enabled_project_ids`、`card_pool`、`event_deck`、`action_card_pool`、`blocked_route_count`、`initial_damage`。
- 任务：`required_domains`、`required_origin_diversity`、`required_card_count`、`reward`。
- 项目：`stages[].action_type`、`required_progress`。
- 文化牌：`domain`、`origin_tags`、`effect`。
- 事件：当前支持的 `damage_open_sites`、`all_influence`、`gain_resource`、`threat`。
- 目标：现有五种 `type`。
- 角色：现有 `ability.action` 与 `ap_cost`。

### 需要小型前后端接入的新增字段

| 字段 | 类型 | 默认值 | 改动点 |
|---|---|---|---|
| `culture_cards[].combo_tags` | `string[]` | `[]` | 后端贡献结算与前端卡牌组合提示 |
| `culture_cards[].combo_with_domains` | `string[]` | `[]` | 任务预览与组合校验 |
| `tasks[].combo_requirement` | `object` | `{}` | `_card_can_contribute`、`_task_complete` |
| `projects[].stages[].requirements` | `object` | `{}` | `_advance_project` |
| `projects[].reward` | `object` | `{}` | 项目完成结算 |
| `sites[].node_ability` | `object` | `null` | 行动 selector、节点效果、Inspector |
| `roles[].upgrade_ids` | `string[]` | `[]` | 角色升级选择 UI |
| `role_upgrades[].effect` | `object` | `{}` | selector 与 effect handler |
| `action_cards[].effect` | `object` | `{}` | 行动牌抽取、使用和弃牌 |
| `event_chains[].event_ids` | `string[]` | `[]` | 事件牌堆构筑与链条状态 |
| `scenarios[].solo_rules` | `object` | `{}` | 创建单人局与双角色控制 |
| `scenarios[].starting_threat` | `number` | `0` | 新局 shared state |
| `scenarios[].starting_clues` | `number` | `0` | 新局 shared state |
| `scenarios[].core_project_id` | `string|null` | `null` | 胜利条件与 UI |
| `difficulty[].event_preview_count` | `number` | `1` | 事件预告 UI |
| `difficulty[].solo_ap_bonus` | `number` | `0` | 单人平衡 |

### 校验规则建议

- 每个情景启用节点必须连通。
- 每个启用任务所需领域与来源必须存在于情景卡池。
- 每个项目必须位于启用节点。
- 角色起点必须始终启用。
- 事件链不得引用不存在事件。
- 组合奖励不能在同一动作中重复触发。
- 单张文化牌只能选择“贡献”或“即时使用”其中一种去向。

## 五、实施优先级

### P0：只替换 JSON 即可获得的提升

- 场景牌库、事件池、启用节点和项目差异。
- 文化牌即时效果分布。
- 任务领域、来源数量和卡牌数量差异。
- 事件文案、预告和缓解建议。
- 项目阶段顺序与推进次数。
- 术语、节点说明和战略提示。

### P1：小型前后端逻辑改造

- 证据组合校验与组合奖励。
- 项目阶段 `requirements` 和 `reward`。
- 节点能力。
- 行动牌进入可抽取、可使用的牌区。
- 角色升级效果。
- 事件链。
- 单人双角色模式。
- 情景核心项目胜利。
- 起始风化压力与研究线索。
- 事件预览数量和事件目标预告。

### P2：不阻塞当前版本的扩展

- 事件链专属动画。
- 结局成就展示。
- 每日 seed。
- 项目分支选择。
- 更细的团队评分和复盘图表。

## 完整版机制包摘要

本数据包以“证据拼图 + 路线治理 + 风险抉择”为核心。四个情景分别突出修护、跨来源协作、路线恢复和综合长局。卡牌不再全部是影响力加一；它们分为机动、修护、风险、项目、组合与结局用途。任务和项目要求玩家跨节点移动、交换、贡献和修护，形成完整因果链。

## 内部资料建议

以下内容在正式文化说明、答辩文本或来源页中需要进一步核对：

- 云冈石窟具体洞窟、造像、纹样和彩绘案例的对应关系。
- 平城遗址具体考古发现、范围与展示表述。
- 华严寺、善化寺现存建筑的结构术语和修缮资料。
- 大同地区长城关堡、烽火台、互市与交通路线的具体地点关系。
- 风化、渗水、裂隙、生物附着等病害的专业分类和处置术语。
- 玩家可见的具体年代、人物、题记、洞窟编号和文物出处。
- 角色身份与真实历史职业体系之间的界限。

这些核验状态不应出现在玩家 UI；玩家界面只展示经过确认的简明文化说明。

## 不要做的机制

- 掷骰走格子、飞行棋式绕圈。
- 以选择题替代文化互动。
- 所有卡牌都只提供数值加一。
- 以战斗、伤害和装备取代修护与协作。
- 无限制增加节点，导致路线网络失去可读性。
- 个人排名或抢分破坏共同目标。
- 付费抽卡、稀有度数值膨胀。
- 将游戏化节点伪装成真实遗址。
