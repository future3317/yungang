# 当前机制与发布安全基线

本文档记录当前可运行的机制合同，作为后续迭代和内容审校的实现基线；带日期的审计记录只描述当时状态，不覆盖本文档。

- 场景牌池只从 `card_pool` 生成，不再把未声明的文化牌默认混入；七个场景均可从首页进入，并显示各自时长。
- `scenario_rule` 已结构化为触发器与效果，运行时在修护、贡献、探索、建立连接和回合结束时显式触发。
- 回合摘要在结算前捕获旧事件、旧目标和规划标记快照。
- 规划阶段可选择地点、路线和项目；项目规划通过统一阶段推进器结算。
- 已删除指定 session 创建和旧玩家加入两个接口，客户端只能创建服务端生成的 session。
- 房间 SSE 使用请求头换取一次性 60 秒订阅票据，长期席位令牌不再进入 SSE URL；席位令牌仅保存在当前浏览器会话。
- 房间码使用 16 位随机标识，并对创建、加入和行动接口启用基础限流与安全响应头。
- `data/*.sqlite3`、Playwright 结果、审计截图、覆盖率和日志均视为本地产物，不提交到仓库；生产旅程和房间保存在 Neon PostgreSQL，不复制进镜像。

## 现行玩法合同

- 单人旅程由一位玩家轮流操作两位角色；本地协作和多设备房间通过席位令牌区分操作者。
- 事件先进入预告，再在回合结束时结算；预告目标、行动预览和结算目标必须一致。
- 玩家先移动到地点，再探索文化证据；证据进入研究台后归入“支持 / 冲突 / 待确认”，形成解释后选择“立即处理 / 最小干预 / 先记录”。
- 路线状态分为畅通、承压和阻断；承压路线仍可通行但增加风险成本，阻断路线不可通行。
- 所有行动合法性、费用、目标和状态变化由后端返回与结算；前端不得根据旧字段重新推断行动。
- 场景胜利条件与失败条件来自场景数据；完成项目阶段看实际行动进度，不以免费行动的资源消耗量冒充完成度。

## 机制数据约定

场景规则必须使用以下结构，不得再使用自由文本替代运行时配置：

```json
{
  "description": "玩家可读的规则说明",
  "trigger": "after_restore",
  "effect": {
    "type": "move_planning_mark_adjacent",
    "amount": 1
  }
}
```

新增效果必须同时注册在 `backend/mechanisms.py`、接入 `backend/engine.py`，并增加行为测试。

## 本地验证

```powershell
conda activate piepaper
cd frontend
npm run typecheck
npm run test -- --run
npm run build
cd ..
python -m pytest -q
python scripts/validate_content.py
```

本地运行数据库可以使用 `data/games.sqlite3`，不要加入 Git；Render 生产数据库由 `DATABASE_URL` 指向 Neon PostgreSQL，应用启动不会重新执行全量迁移。
