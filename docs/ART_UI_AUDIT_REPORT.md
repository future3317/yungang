# 云冈遗产网络 Phase 3 视觉与机制审计

## 结论

主界面已从“发光网络图”收敛为“大同文化舆图”：四个区域提供低对比度地理分组，节点是可点击的遗产地点或设施，路线只在需要决策时显现。传统素材进入节点详情、事件预告、证据牌和结果页，不再铺满地图背景。

## 已完成

- 移除地图中央佛像、路线 PNG、全局 `screen` 混合和拉伸路线图片。
- 路线统一为单条无向数据记录，前端用 SVG Bézier `path` 绘制；默认只显示主干、当前邻接和异常路线。
- 区域标签使用 `regions.json` 的固定 `label_position`，不再由节点平均坐标生成。
- 节点分为核心遗产、支撑设施和临时事件三种，节点详情进入现有上下文面板。
- 节点使用 LOD：远景只显示区域、核心节点和主干；近景再显示设施、风险、玩家和标签；节点图标保持屏幕空间尺寸。
- 默认标准局启用 12 个节点，市场重开启用 10 个，文明汇流启用 12 个，长局启用 15 个。
- 项目阶段按 `explore -> contribute -> restore` 的不同动作推进，不再由任意贡献自动推进。
- `prepare`、和合能力、贡献加成、角色升级入口、行动牌牌库、弃牌堆、档案区和规划标记均写入游戏状态及日志。

## 未完成与风险

- `data/` 中仍有 `placeholder` 和 `TODO_CONTENT_REVIEW` 内容；它们只能作为内部游戏化占位，不能作为正式文化事实发布。
- Playwright 多视口截图、axe 和 Lighthouse 尚未形成当前版本的基线产物。
- Storybook 资源单项审查和 unused / duplicated / stretched 自动扫描仍需在发布前接入 CI。
