# 《云冈飞天棋：文明互鉴之路》美术与界面审查报告

> 审查目标：从游戏大厂工业化标准 + 中国审美视角，评估当前前端布局、视觉细节、字体、交互与可用性。  
> 审查范围：`frontend/index.html`、`frontend/static/css/styles.css`、`frontend/static/js/app.js`、UI 资源包、`data/game_data.json`。  
> 审查工具：Playwright（开源浏览器自动化）拍摄 6 种视口截图并提取计算样式；人工视觉检查；WCAG 对比度计算。

---

## 1. 审查方法与数据来源

1. 用 Playwright 在 `1920×1080`、`1440×900`、`1280×800`、`1180×800`、`768×1024`、`390×844` 六个视口下启动游戏、选择角色、掷骰、抽卡并截图。
2. 提取关键 DOM 元素的 `width/height/top/left`、`font-size`、`line-height`、`font-family`、`color`。
3. 输出保存在：
   - `audit_output/desktop_1920.png` 等截图
   - `audit_output/metrics.json`
   - 复用脚本：`scripts/audit_screenshots.py`

> 当前项目的 Skill 列表里没有现成的美术/界面审计 Skill。推荐用 **Playwright + axe-core + Lighthouse** 组合做成可复用的开源审计流程，后文第 7 节会给出具体方案。

---

## 2. 整体印象（做得好的地方）

- **文化定位清晰**：暖博物馆色系（象牙、砂岩、赭石、石青、朱砂）与云冈造像、莲花、祥云、印章元素形成统一视觉语言，符合“文明互鉴”主题。
- **字体选择合理**：标题用楷体/思源宋体，正文用苹方/微软雅黑，是中式界面的稳妥做法。
- **信息分区清晰**：左侧棋盘 + 右侧功能面板的经典桌游布局；标题、控制、图卷、玩家、手牌、卡牌、日志各司其职。
- **动效有细节**：`pulseSpace`、`bounceToken`、`flipIn`、`dealIn` 等动画增加了仪式感。
- **资源美术质量高**：佛像浮雕、角色徽章、遗产节点徽章风格统一、细节丰富。

## 3. 关键问题（按严重度排序）

### P0 — 必须立即修复

#### 3.1 移动端/平板端棋盘水平溢出（最严重的布局 Bug）

**表现**：
- `390px` 视口下，`.page` 宽度只有 `374px`，但 `.board-wrap` 实测宽度 `683px`，`.side` 实测 `725px`，整页出现严重水平滚动/裁剪。
- `768px` 视口下同样发生溢出。

**根因**：
- `styles.css:250-262` 给 `.board-wrap` 设置了 `aspect-ratio: 1 / 0.82` 和 `min-height: 680px`。
- 响应式媒体查询（`styles.css:1232-1250`）在窄屏把 `.board-wrap` 的 `min-height` 改为 `560px` / `620px`，但没有移除或覆盖 `min-height`。
- 当容器宽度 < `min-height / 0.82` 时，`min-height` 会撑大元素宽度，导致单栏布局被撑破。

**数据**：

| 视口 | `.page` 宽度 | `.board-wrap` 宽度 | 理论应占宽度 |
|---|---|---|---|
| 1920×1080 | ~1421px | 1016px | 正常 |
| 1280×800 | ~1182px | 765px | 正常 |
| 768×1024 | ~737px | 756px | 应 ≤ 737px，已溢出 |
| 390×844 | ~374px | 683px | 严重溢出 |

**建议**：
```css
@media (max-width: 760px) {
  .board-wrap {
    min-height: auto;          /* 移除最小高度 */
    width: 100%;
    height: auto;
    aspect-ratio: 1 / 0.82;    /* 让高度随宽度自然缩小 */
  }
}
```
若觉得棋盘在手机上太小，可改为：
1. 给棋盘加一个 `overflow: auto` 的容器，保留 `min-width: 720px`，允许用户左右拖动或双指缩放；
2. 或者在小屏切换为竖向/线性路径，减少宽度需求。

---

#### 3.2 右侧“文化卡牌”区域大量留白，信息密度极低

**表现**：
- 桌面端右侧固定 `400px`，卡牌框架 `06_vertical_card_frame.png` 是竖版 `1086×1448`（高宽比约 1.33）。
- 在 `400px` 宽容器里，卡牌实际内容区宽度仅 `289px`，卡牌标题 `26px`，正文 `13px`，而框架下半部分基本是空的。
- 在移动端，卡牌框架被进一步放大到接近全屏，但有效文字仍集中在顶部一小条。

**根因**：
- `styles.css:765-831` 使用竖版装饰框架作为背景，而内容以 `position: absolute` 嵌入，导致“框大文少”。

**建议**：
1. **首选**：把右侧“文化卡牌”改成横版卡片或紧凑卡片列表，装饰框架仅作卡片边缘点缀；
2. 若坚持用竖版框架，应在框架内增加：卡面插画、水印纹理、二维码/来源链接，让内容填满视觉空间；
3. 移动端直接把卡牌内容放出手牌区，避免一个巨大空框独占一屏。

---

#### 3.3 操作按钮缺少加载/禁用状态，容易重复提交

**表现**：
- `app.js:426-446` 中“掷骰子”“抽文化卡”点击后没有置灰或 `loading` 状态。
- 网络延迟时用户可能连续点击，导致后端收到多次请求、日志重复、状态异常。

**建议**：
- 在 `await Api.roll()` / `await Api.drawCard()` 期间给对应按钮加 `disabled` 和旋转/闪烁提示；
- 所有异步操作统一加一个全局 `isLoading` 锁。

---

#### 3.4 回合流程不清晰，缺少“结束回合”提示

**表现**：
- 规则说明“每回合可打出 1 张”，但界面没有显示当前处于“掷骰阶段”“出牌阶段”还是“抽卡阶段”。
- “掷骰子”会自动结束回合（`app.py:305` `end_turn`），但“抽文化卡”不会；玩家容易困惑为什么有时可以连续操作、有时不行。

**建议**：
- 增加回合阶段指示器（如“① 掷骰 → ② 出牌/抽卡 → ③ 结束”）；
- 非当前阶段按钮置灰；
- 或增加显式“结束回合”按钮，把主动权交给玩家。

---

### P1 — 重要但可后续迭代

#### 3.5 图片资源体积过大，严重影响首屏加载

**数据**：

| 文件 | 尺寸 | 用途 | 问题 |
|---|---|---|---|
| `01_buddha_relief_medallion.png` | 2.5 MB | 棋盘中央佛像 | 过大 |
| `05_heritage_medallion_set.png` | 2.0 MB | 6 个遗产节点 | 过大 |
| `07_role_badge_set.png` | 1.9 MB | 4 个角色徽章 | 过大 |
| `06_vertical_card_frame.png` | 1.5 MB | 卡牌框 | 过大 |
| `08_horizontal_banner_frame.png` | 1.4 MB | 标题横幅 | 过大 |
| `02_cloud_ribbon_divider.png` | 1.1 MB | 仅作 `72×10` 小装饰 | 严重浪费 |
| 各 `_orig.png` | 共约 10 MB | 未被代码引用 | 仓库冗余 |

**建议**：
- 将所有装饰性 PNG 转为 **WebP/AVIF**，并压缩到原大小的 20%-40%；
- 对云纹分隔线这种小装饰，用 CSS/SVG 重绘或压缩到 <50 KB；
- 删除或移出 `_orig` 原图，CI/CD 时再按需生成；
- 佛像、徽章等可加 `loading="lazy"`，中央佛像因首屏需显示可保留但应压缩。

---

#### 3.6 字体依赖系统字体，跨平台一致性差

**表现**：
- `styles.css:35` 和 `:103` 使用 `"STKaiti", "KaiTi", "Source Han Serif SC"...` 等系统字体。
- Windows 有楷体、macOS 有华文楷体，但 Linux 和移动端很可能 fallback 到普通宋体或 sans-serif，破坏中国风气质。

**建议**：
- 引入 Google Fonts 或阿里普惠/思源宋体 Web Font：
  ```html
  <link href="https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@400;700&display=swap" rel="stylesheet">
  ```
- 标题 `font-family: "Noto Serif SC", "STKaiti", "KaiTi", serif;`
- 设置 `font-display: swap` 避免阻塞渲染。

---

#### 3.7 棋格与节点缺乏无障碍支持

**表现**：
- SVG 棋格（`.space`）和遗产节点（`.node`）仅靠 `mouseenter`/`click` 触发提示，键盘用户和屏幕阅读器无法操作。
- 角色棋子（`.token`）是 `div`，没有 `aria-label`。

**建议**：
- 给 `.space` 加 `role="button" tabindex="0" aria-label="造像格：莲"`；
- 给 `.node` 加 `aria-label="云冈石窟：中心遗产节点"`；
- 给 `.token` 加 `aria-label="当前玩家：平城工匠，第 3 格"`；
- 为键盘用户补全 `Enter`/`Space` 触发逻辑。

---

#### 3.8 同格棋子几乎完全重叠

**表现**：
- `app.js:161-166` 的偏移量被转成百分比：
  ```js
  style="left:${(coord.x + offset[0]) / 10}%;top:${(coord.y + offset[1]) / 8.2}%;"
  ```
- `offset[0]` 只有 `±1.6`，除以 10 后仅 `±0.16%`，在 `1000px` 棋盘上只有约 `1.6px`，视觉上等于没有偏移。

**建议**：
- 使用固定像素偏移（如 `±14px`）或按棋盘比例计算，确保 2-4 个棋子同格时明显错开。

---

#### 3.9 棋格 Tooltip 内容重复

**根因**：
- `app.js:136`：
  ```js
  tooltip.innerHTML = `<strong>${s.label}</strong><span>${s.label}</span>`;
  ```
- 强标签和正文显示同一个词，没有额外说明。

**建议**：
- 改为显示 `图标 + 类型 + 简短效果`，例如“莲 造像格：停留可获得造像印记”。

---

#### 3.10 胜利弹窗背景图被拉伸变形

**根因**：
- `styles.css:1104`：`background: url(...) center / 100% 100% no-repeat`，把 `4:3` 的横幅框强行拉伸到弹窗比例。

**建议**：
- 改用 `background-size: cover` 或 `contain`，或准备专门的竖版胜利框。

---

### P2 — 细节打磨

#### 3.11 标题横幅与文字层级略抢

- `08_horizontal_banner_frame.png` 两侧有红色莲花装饰，`opacity: 0.38` 仍与标题文字竞争注意力；可在文字区域加更强的不透明底或继续降低装饰层透明度。

#### 3.12 棋格视觉风格与精美资源不匹配

- 棋盘路径、棋格是扁平矢量圆点，而佛像、徽章是写实/插画风格，两者质感割裂。
- 建议：把棋格做成“印章”“莲花瓣”或“石窟龛”形状，路径加入手绘/石刻纹理。

#### 3.13 共同图卷进度条缺少里程碑感

- 进度条高度 `18px`，仅显示数字 `0 / 10`；可在进度条上方加入 5 个文明印记小图标作为里程碑。

#### 3.14 骰子只是方块 + 汉字，缺少“掷”的反馈

- 点击后数字直接切换，没有掷骰动画；可加入 2-3 帧快速切换 + 音效/震动，强化桌游感。

#### 3.15 手牌区域视觉层级弱

- `.hand-card` 尺寸 `128×92px`，没有使用卡牌框资源，与下方华丽的“文化卡牌”区形成落差。
- 建议给手牌也加轻量边框/云纹，保持成套感。

## 5. 竞品与优秀案例借鉴

1. **《江南百景图》**：古风 H5/手游常用“可缩放画布 + 底部操作栏”解决小屏地图问题；其色彩克制、留白讲究，值得参考。
2. **《花亦山心之月》**：国风卡牌 UI 会把卡面插画作为视觉主体，文字压在不透明底上，既保留边框装饰又不空框。
3. **Carcassonne / Ticket to Ride App**：桌游数字化的标杆——棋盘可双指缩放、手牌在底部横向滑动、回合阶段用高亮按钮明确提示。
4. **排版参考**：[Typography and Usability in Game Design](https://dtc-wsuv.org/klindsey17/typographyFinal/) 指出游戏 UI 必须保证“可立即识别”的字号与对比度；本项目正文 13-15px 基本达标，但卡牌区可再放大。
5. **中国风 UI 参考**：[游戏UI设计精品教程之中国风界面设计技法](http://www.eduaab.com/6189/c_109139.html) 强调传统纹样、色彩、字体三维统一，本项目已具备雏形，但需在“模块形状”上再做文章。

## 7. 怎么用 MCP / 开源 Skill 做这类审计

当前 Kimi Code 的 Skill 列表里没有专门的游戏美术审计 Skill，但可以快速搭一套可复用的开源审计流水线：

### 7.1 已落地的 Playwright 审计脚本

- 文件：`scripts/audit_screenshots.py`
- 能力：
  - 多视口截图
  - 提取关键元素计算样式
  - 输出 `audit_output/metrics.json`
- 运行：
  ```bash
  python scripts/audit_screenshots.py
  ```

### 7.2 推荐接入的开源工具

| 工具 | 作用 | 接入方式 |
|---|---|---|
| **Playwright** | 跨浏览器截图、交互、提取样式 | Python/Node 脚本 |
| **axe-core** | 自动化无障碍检查 | `axe-playwright` 或注入 JS |
| **Lighthouse** | 性能、可访问性、最佳实践 | CLI / CI |
| **BackstopJS** / Playwright `toHaveScreenshot` | 视觉回归 | CI 对比基线截图 |
| **ImageMagick / squoosh-cli** | 图片压缩、格式转换 | CI 自动转 WebP |

### 7.3 可封装成项目级 Skill 的 prompt 模板

```text
请作为游戏美术与 UI 审计专家，对 {project_path}/frontend 进行审查：
1. 用 Playwright 在 1920/1440/1280/768/390 视口截图；
2. 检查响应式布局是否溢出；
3. 列出字体、字号、对比度问题；
4. 检查图片体积与格式；
5. 给出 P0/P1/P2 优化清单与具体代码位置。
```

### 7.4 是否值得做 MCP Server

- 如果团队经常做 H5/小游戏，可以做一个 **“Browser Audit MCP Server”**：输入 URL，返回截图、布局指标、Lighthouse 分数、axe 报告。
- 当前项目规模较小，直接复用 `scripts/audit_screenshots.py` 即可，不需要额外的 MCP 基础设施。

## 9. 总结

《云冈飞天棋》在**色彩体系、文化符号、美术资产**上已经具备较高的审美水准，核心问题集中在：

1. **响应式布局失控**（棋盘 min-height 与 aspect-ratio 冲突）；
2. **信息密度失衡**（右侧卡牌区空框太大）；
3. **交互状态缺失**（按钮 loading、回合阶段不清）；
4. **性能包袱重**（PNG 资源过大）。

优先修复 P0 问题后，项目即可从“原型”跃升到“可参赛/可演示”的品质；P1/P2 完成后将更接近商业级文创游戏的标准。

棋盘四路汇聚重构后，视觉主题性与可识别度显著提升，可作为后续迭代的基础。
