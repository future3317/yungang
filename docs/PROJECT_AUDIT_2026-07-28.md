# 项目级工程审查记录（2026-07-28）

## 本轮审查范围

- 前端页面、游戏 HUD、地图、Inspector、行动选择和房间状态反馈。
- 前端共享 API、SSE 事件订阅、行动组装和内容标签文案。
- 后端房间权限、运行时内容校验和现有测试入口。
- `data/` 现行运行时数据、`docs/` 产品状态文档和历史归档边界。

## 本轮已完成

### 交互与视觉结构

- Inspector 使用固定的摘要、标签和滚动内容区，任务内容不会再把“任务 / 事件 / 市场”标签推开或覆盖。
- Inspector 标签具备独立的键盘语义、面板关联和稳定点击层级。
- 行动、手牌、任务指引中的按钮补齐 `type="button"`，避免嵌套表单时误提交。
- 清理游戏运行时前端的乱码文案，保留主题一致的中文反馈和行动说明。

### 共享代码

- `widgets/game/gameUi.ts` 统一行动名称、行动目标组装、行动反馈、卡牌行动查找、差异摘要和角色徽章路径。
- `widgets/game/contentLabels.ts` 统一领域名称、组合标签和内容标签。
- Inspector、JourneyGuide、CommandDock 不再各自维护重复的领域和组合文案。

### 房间实时状态

- 房间 SSE 每次连接先申请短时订阅票据。
- 临时断线使用指数退避重连，正常流结束快速重连。
- 席位票据失效时停止无意义重试，并把“席位失效”反馈给游戏页状态栏。
- 游戏页区分“同步中 / 已连接 / 重连中 / 重新连接 / 席位失效”。

## 当前不可破坏约束

- 合法行动、目标、成本和 `revision` 仍由后端返回，前端不复制规则判定。
- 房间游戏继续使用房间专用读取和操作接口，不回退到无席位的普通游戏接口。
- `data/legacy/` 仅作历史归档，不进入当前运行时内容池。
- 文化内容的事实分类、来源和授权信息不能由界面文案替代。
