# 游戏视口、路线层与反馈闭环设计

## 目标

把游戏页从多套相互覆盖的固定定位规则收敛为一个世界层加 HUD 槽位系统，并让路线、胜利条件、行动反馈和历史记录共享同一套视觉与数据表达。

## 当前问题

- 地图使用全屏世界层，但胜利清单、路线检查器、时间线和多个提示仍各自计算 `fixed` 坐标。
- 路线选择状态使用过强的几何高亮，遮挡节点和文字，路线检查器也没有稳定锚点。
- 行动反馈和部分弹窗没有统一的深色主题容器，存在白色默认表面。
- `FeedbackChange` 已结构化，但历史记录和部分 UI 仍按旧字典格式渲染，无法解释变化的含义。
- 内部 `type/status/target_rule/effect.type` 仍可能直接进入玩家界面。

## 设计

### 1. GameViewport

`GameViewport` 负责唯一的几何结构：地图为 `absolute inset: 0` 的世界层；HUD 使用 `top`、`left`、`center`、`right`、`bottom` 五个槽位；弹窗和提示统一进入 overlay 层。业务组件不再自行计算 viewport 的 `left/right/top/bottom`。

迁移顺序：场景标题和胜利清单进入 top；玩家栏和行动区进入 left；地图、路线检查器和行动模式提示进入 center；地点检查器和历史记录进入 right；时间线与回合摘要进入 bottom/overlay。

### 2. 路线视觉

普通路线保持低对比度持续显示；相邻路线提高对比度；合法目标路线使用语义色和短暂显影；路线状态同时由颜色和线型表达。路线检查器固定在 center 槽位的可用区域内，不覆盖胜利清单、节点标签或右侧 inspector。节点标签使用已有避让布局，不再通过矩形框包围路线区域。

### 3. 统一变化展示

新增 `StateChangeList` 作为行动反馈、事件预览、回合摘要、历史记录的唯一展示组件。输入为结构化变化对象，显示指标中文名、前值、后值和方向，例如“风化压力 2 → 3”“研究线索 +1”。只使用 `weathering_track`，不重复展示 legacy `threat`。

### 4. 术语与表面

所有玩家可见枚举通过统一 formatter 转成中文；UI 禁止直接渲染内部 ID。Dialog、Popover、Toast、Timeline 和行动反馈统一使用深绿暖石纸主题，不允许浏览器默认白色表面进入玩家路径。

## 实施边界

第一批修改涉及游戏页布局、地图路线层、反馈/历史展示、术语 formatter 和相关样式。机制模拟、后端强类型和完整 E2E 在第一批视觉回归稳定后进入后续批次，不在同一补丁中混杂。

## 验证标准

- 1280×800、1440×900、1920×1080 下胜利清单、路线检查器、左右栏无重叠。
- 路线选择不会产生矩形遮挡或白色弹层。
- 行动反馈、事件结算和历史记录显示中文指标及真实前后变化。
- 玩家可见 UI 不出现英文内部枚举。
- `npm run typecheck`、`npm run test -- --run`、`npm run build`、`pytest -q` 和已有 Playwright 检查通过。
