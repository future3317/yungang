# Phase 3 视觉与机制审计

## 原实现问题

- 地图同时绘制 SVG 线和路线 PNG，且路线 PNG 被 `preserveAspectRatio="none"` 拉伸。
- 全局 `screen` 混合使所有路线、边框和背景争夺注意力。
- 中央佛像与地图背景混在同一层，节点是统一的深色卡片，区域标签由节点平均值生成。
- 默认页面同时固定展示 roster、任务、事件、市场、行动台和时间线，1440x900 下内容互相挤压。
- `prepare` 只写入事件 id，项目阶段按任意贡献推进，文化卡牌重复三次，场景没有完整筛选内容。

## Phase 3 改造基线

- 地图采用四个区域的低对比度形状，路线默认只显示主干、当前邻接和异常路线。
- 路线统一为服务端 route 的单条无向记录，前端用 SVG Bézier path 绘制。
- 节点分为核心遗产、支撑设施、临时事件三种，详情进入右侧上下文区域。
- 事件准备、卡牌即时使用、项目阶段、节点能力和规划标记必须改变可观察状态并写入日志。

## 未审校内容

当前 `data/` 中仍有 `placeholder` 和 `TODO_CONTENT_REVIEW` 字段。它们只能作为非默认场景的内容池，不能作为传统文化事实对外宣称；正式发布前需要逐条补充来源、时代和审校结论。
