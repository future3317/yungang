## UI 与空间

- 当前游戏页是左侧 roster、中间地图、右侧上下文的三栏结构，地图不是主舞台。
- 底部 action dock 固定占用约 240px，地图高度使用 `min(680px, 62vw)`，1440x900 下无法形成全屏世界视图。
- 地图节点和关系线已有元数据来源，但尚未分出 region、site facet 和 project 三层语义。
- 时间线位于页面底部，尚未成为右侧抽屉；任务、事件和市场持续占据固定面板。
- 当前正文基础字号为 14px，多个标签和辅助文本为 9-13px，不满足 Phase 2 的中文可读性目标。

## 随机性与重玩性

- `GameEngine.new_game()` 直接按内容文件顺序分配角色、文化牌和事件。
- 没有 seed、RNG position、洗牌状态或可重建的随机快照。
- 创建游戏请求没有场景、seed 或每日旅程参数。
- 相同玩家人数会得到相同的开局牌序和事件顺序。

## 规则与终局

- 路线只有 `routes.json` 中的静态方向和 cost，没有 `open/strained/blocked/restored/illuminated` 状态。
- `legal_actions` 是扁平字典列表，动作目标和预览信息由前端自行推断。
- 只有即时修护、贡献和探索，没有调查、准备、路线修护、多阶段项目或角色成长。
- 胜利和失败条件集中在 `_check_outcome()`，当前只有完成领域/共同影响、关闭节点数和回合上限。
- 终局没有评分、seed 复盘、关键组合、最危险时刻或未完成目标。

## 工程阻塞点

- `GamePage.tsx` 仍承载页面编排、动作选择、市场、手牌、弹窗和终局渲染。
- `GameState` 为 v2，`tasks`、`pending_choice` 和 `legal_actions` 仍是宽泛字典结构。
- Repository 的 session id 使用 `COUNT(*) + 1`，创建和 revision 检查不是单一原子事务。
- 内容文件缺少统一术语表和内容审核元数据校验。

## Phase 2 优先级

1. 先建立可迁移的 schema v3 和术语表，保留 v2 读取路径并明确标记 legacy。
2. 再实现 seed、场景、路线状态和多阶段项目，使每局实际改变地图和事件。
3. 最后将地图升格为全屏舞台，并把固定面板改为按需抽屉。
